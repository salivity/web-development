Web MIDI API: Connecting Web Apps to Musical Hardware

The Web MIDI API bridges the gap between web applications and physical musical instruments, enabling browsers to communicate directly with external MIDI devices like synthesizers, drum pads, and digital audio workstations. By providing a standardized interface for sending and receiving raw MIDI messages without specialized plugins or software installations, the API transforms the browser into an interactive environment for music creation, performance, and hardware management.

Accessing MIDI Devices

Communication begins with the navigator.requestMIDIAccess() method. Because connecting to external hardware introduces privacy and security considerations, modern browsers prompt the user for permission before granting access.

Once granted, the API returns a MIDIAccess object that represents the connection to the host system’s MIDI subsystem. This object maintains dynamic registries of both inputs (devices sending data to the computer, such as keyboards) and outputs (devices receiving data from the computer, such as sound modules). It also listens for state changes, allowing web apps to detect when hardware is plugged in or disconnected in real time.

Receiving Input from Musical Hardware

To capture performance data from an external controller, developers attach an event listener to the desired MIDIInput port using the midimessage event.

Whenever a musician interacts with the hardware—such as pressing a key, turning a knob, or hitting a drum pad—the device generates standard MIDI data packets. The browser captures these packets as raw byte arrays:

  • Status Byte: Indicates the type of action (e.g., Note On, Note Off, Control Change) and the MIDI channel (1–16).
  • Data Byte 1: Identifies the specific parameter, such as the note number (pitch) or controller number.
  • Data Byte 2: Specifies the value, such as velocity (how hard a key was struck) or parameter intensity (0–127).

Web applications parse these byte arrays to trigger web-based sound engines, manipulate WebGL graphics, or record musical performances directly into an online timeline.

Sending Data to External Instruments

The Web MIDI API also supports bidirectional communication by allowing web applications to transmit data via MIDIOutput ports using the send() method.

Developers pass an array of unsigned 8-bit integers representing standard MIDI instructions to the output device. This enables web platforms to:

  • Act as sequencers or arpeggiators that trigger notes on physical analog or digital synthesizers.
  • Send Control Change (CC) messages to automate hardware filters, volume, and modulation.
  • Transmit System Exclusive (SysEx) messages, which allow deep integration such as backing up device presets, transferring firmware updates, and building visual patch editors directly in the browser.

Low Latency and System Integration

The Web MIDI API relies on the underlying operating system's native MIDI drivers (such as CoreMIDI on macOS or ALSA on Linux). By interacting directly with the OS subsystem rather than emulating device protocols, the API achieves the low-latency performance essential for live musical timing and synchronized playback.
