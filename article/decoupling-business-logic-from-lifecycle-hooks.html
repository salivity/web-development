Decoupling Business Logic from Lifecycle Hooks

Coupling core business logic directly to framework-specific lifecycle hooks—such as React's useEffect, Vue's onMounted, or Angular's ngOnInit—creates brittle, untestable applications that are difficult to refactor. This article outlines the strategies software engineers use to isolate domain rules from UI runtime events, including extracting pure domain services, utilizing headless architectural patterns, and adopting event-driven and state machine architectures to keep frameworks strictly at the application's boundary.

The Problem with Lifecycle Coupling

Lifecycle hooks are designed to coordinate a component with external systems (such as the DOM, network requests, or subscriptions) relative to when a component renders or unmounts. When developers embed calculations, validation, and domain state mutations directly inside these hooks, several problems emerge:

  • Testability degradation: Testing business rules requires rendering a virtual component and simulating its lifecycle phases, slowing down test suites and increasing maintenance overhead.
  • Framework lock-in: Upgrades or framework migrations require rewriting both UI and core logic.
  • Hidden execution flows: Lifecycle hooks often trigger unexpected multi-pass re-renders or race conditions because logic is tied to presentation state instead of explicit user actions.

1. Extract Logic into Plain TypeScript/JavaScript Services

The most effective method for decoupling is creating framework-agnostic modules—often termed domain services, use cases, or Plain Old JavaScript Objects (POJOs).

A domain service should be written entirely in standard TypeScript without importing framework tokens:

// cart.service.ts (Framework-agnostic)
export class CartService {
  calculateTotal(items: CartItem[], discount: Discount): number {
    const subtotal = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
    return subtotal - (subtotal * discount.rate);
  }
}

By extracting the rules into a pure class or set of functions, unit testing requires only standard assertion runners (like Vitest or Jest) without needing component-mounting libraries.

2. Treat Lifecycle Hooks as Translators

Under clean architecture principles, lifecycle hooks belong to the "infrastructure" or "presentation" layer. Their sole responsibility should be translating a lifecycle event into an input for the domain layer, acting like a bridge.

Instead of writing data transformations within a hook:

  1. The lifecycle hook fires (e.g., component mounts).
  2. The hook calls a decoupled use case or handler function.
  3. The hook receives the output and updates local component state, if necessary.
// React example: Hook acts strictly as an adapter
function UserProfile({ userId }: { userId: string }) {
  const [user, setUser] = useState<User | null>(null);

  useEffect(() => {
    let isSubscribed = true;
    
    // Pure async domain function defined outside the component
    fetchUserProfile(userId).then(profile => {
      if (isSubscribed) setUser(profile);
    });

    return () => { isSubscribed = false; };
  }, [userId]);

  return <div>{user?.name}</div>;
}

3. Implement Headless Hooks and Composables

Frameworks like React and Vue support idiomatic encapsulation through custom hooks and composables. Engineers use "headless" patterns to divide responsibilities:

  • View Layer: Defines layout, styling, and binds event listeners.
  • Controller Layer (Custom Hook/Composable): Manages framework lifecycles and reactive primitives.
  • Domain Layer (Pure Modules): Holds the business logic, independent of any UI framework.

The custom hook acts as a facade, binding framework reactivity (e.g., ref, useState) to the pure logic modules, ensuring the actual business logic remains isolated from framework-specific APIs.

4. Rely on Finite State Machines (FSMs)

Complex lifecycle logic often arises when trying to synchronize asynchronous states (loading, error, success, retry) within hooks. Finite state machines (such as XState) decouple this logic completely.

With a state machine:

  • State transitions and side effects are defined in an independent machine configuration.
  • The UI component simply sends events (e.g., FETCH_DATA) inside a lifecycle hook.
  • The machine handles transition rules, preventing invalid states regardless of how often a component re-renders or mounts.

5. Dependency Injection and Ports & Adapters

In larger systems, engineers apply Ports and Adapters (Hexagonal Architecture). The core business logic defines interfaces (ports) for required side effects, such as an HTTP client or cache storage. Concrete implementations (adapters) are passed into the business logic.

When a lifecycle hook runs, it invokes a domain controller that has already received its dependencies. This approach allows developers to run the exact same domain workflow inside a CLI, a web component, or an automated integration test simply by swapping the adapter.
