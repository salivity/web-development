Using Fetch Priority to Optimize Asset Loading

The fetchpriority attribute is a modern web platform feature that allows developers to signal the relative priority of critical resources directly to the browser. This article explores how fetchpriority works, the problems it solves in resource scheduling, its direct impact on performance metrics like Largest Contentful Paint (LCP), and practical strategies for implementing it effectively in web applications.

The Challenge of Browser Resource Scheduling

Browsers follow complex internal heuristics to determine the order and priority in which assets—such as scripts, stylesheets, fonts, and images—are downloaded. Typically, render-blocking CSS and fonts are treated as high priority, while images and asynchronously loaded scripts receive lower priority.

However, the browser's preload scanner cannot always infer human intent or immediate visual importance. For instance, a critical hero image required for the Largest Contentful Paint (LCP) may be assigned the same low default priority as an off-screen footer image, leading to network contention and delayed rendering.

What the fetchpriority Attribute Does

The fetchpriority attribute provides an explicit hint to the browser’s network stack regarding how urgently a specific resource should be fetched relative to other assets of the same type. It accepts three possible values:

  • high: Signals that the asset should be prioritized ahead of other resources of the same type.
  • low: Signals that the asset can be deferred or fetched with lower urgency.
  • auto: The default state, which relies on the browser's standard prioritization logic.

This attribute works across various HTML elements, including <img>, <link>, <script>, and within the JavaScript fetch() API.

Core Use Cases

1. Accelerating the Largest Contentful Paint (LCP) Image

The most impactful application of fetchpriority is boosting the LCP element. By adding fetchpriority="high" to an above-the-fold hero image, the browser requests it concurrently with critical CSS or scripts rather than queuing it behind them:

<img src="hero-banner.jpg" alt="Featured Product" fetchpriority="high">

2. Deprioritizing Non-Critical Assets

Network bandwidth is finite. Demoting non-essential resources prevents them from competing with critical rendering assets. Adding fetchpriority="low" to secondary elements, such as image carousel slides or low-priority background scripts, preserves bandwidth for essential page components:

<img src="carousel-slide-2.jpg" alt="Secondary item" fetchpriority="low">
<script src="analytics.js" async fetchpriority="low"></script>

3. Tuning Preloaded Resources

When using <link rel="preload">, the browser automatically assigns high priority. However, if multiple resources are preloaded simultaneously, they can contend with one another. Using fetchpriority="low" inside a preload tag allows the browser to discover an asset early without letting it bottleneck more critical resources:

<link rel="preload" href="supplemental-font.woff2" as="font" type="font/woff2" crossorigin fetchpriority="low">

How fetchpriority Differs From Other Directives

  • Compared to loading="lazy": Lazy loading stops a download completely until the element nears the viewport. In contrast, fetchpriority adjusts download urgency but does not prevent the fetch from starting.
  • Compared to async and defer: The async and defer attributes dictate execution timing and render-blocking behavior for scripts. The fetchpriority attribute specifically influences network download ordering.

Best Practices

To achieve optimal performance, reserve fetchpriority="high" for only one or two critical assets per page, typically the primary hero image or an essential modular script. Overusing high eliminates prioritization benefits by recreating network congestion, effectively returning the browser to an unmanaged state.
