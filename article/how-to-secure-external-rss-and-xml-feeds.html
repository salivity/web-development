How to Secure External RSS and XML Feeds

Consuming external RSS and XML feeds exposes web applications to critical vulnerabilities, including XML External Entity (XXE) injection, Server-Side Request Forgery (SSRF), Cross-Site Scripting (XSS), and Denial of Service (DoS) attacks. Because external data is untrusted by default, development teams must treat incoming feeds as potential attack vectors. This guide outlines the essential security controls and architectural practices required to safely ingest, parse, and display external feed data without compromising your application's infrastructure or users.

Disable External Entity Resolution (Prevent XXE)

XML External Entity (XXE) attacks occur when an XML parser processes external entity references defined within the feed's Document Type Definition (DTD). Attackers can exploit this to read local files, access internal networks, or execute arbitrary requests.

  • Disable DTDs entirely: Configure your XML parser to disallow inline DTD processing completely (e.g., disallow-doctype-decl in Java, or setting FEATURE_SECURE_PROCESSING).
  • Disable external entities: If DTDs cannot be fully disabled, explicitly turn off external general entities (load-external-dtd = false) and external parameter entities.
  • Use modern, safe parsers: Ensure parsers are updated to versions where external entity resolution is disabled by default (such as modern versions of Python's defusedxml or PHP's libxml).

Protect Against Server-Side Request Forgery (SSRF)

When fetching external feeds, your backend server makes outbound HTTP requests. If users can supply feed URLs, attackers may target internal services, cloud metadata endpoints, or local interfaces (e.g., localhost, 169.254.169.254).

  • Validate feed URLs against an allowlist: Where possible, restrict feed fetching to explicitly pre-approved domains.
  • Block private and loopback IP ranges: Validate the target IP address after DNS resolution. Reject requests pointing to private CIDR blocks (RFC 1918), link-local addresses, and loopback ranges.
  • Prevent DNS rebinding: Perform the request directly to the validated IP address rather than re-resolving the hostname, ensuring the destination does not change between validation and connection.
  • Disable HTTP redirects: Disallow automatic redirects, or strictly re-validate the target URL upon every redirect to prevent redirection to internal resources.

Defend Against Denial of Service (DoS)

Malicious or malformed XML files can consume excessive memory and CPU resources, causing the application to crash or freeze.

  • Limit request size: Restrict the maximum payload size your application will download (e.g., limit responses to 5 MB or 10 MB).
  • Enforce network timeouts: Set aggressive connection and read timeouts (e.g., 3 to 5 seconds) to prevent slow-loris style connection-holding attacks.
  • Prevent XML Entity Expansion ("Billion Laughs" attack): Ensure your parser enforces strict limits on recursive entity expansion and node depth.
  • Implement caching: Store parsed feeds locally with a sensible Time-To-Live (TTL). Caching prevents your server from repeatedly hitting external servers and shields your parser from repeated payload evaluation.

Sanitize Feed Content (Prevent Stored XSS)

RSS and Atom feeds often contain raw HTML or CDATA blocks within elements like <title>, <description>, or <content:encoded>. Blindly rendering this data in the browser leads directly to Stored Cross-Site Scripting.

  • Apply contextual output encoding: Always encode data for the target context (HTML entity encoding for browser rendering).
  • Use robust HTML sanitization libraries: If rendering rich HTML from the feed is required, pass the content through a trusted, battle-tested sanitizer (such as DOMPurify for JavaScript or Bleach for Python) that strips out <script>, <iframe>, onload, and other dangerous attributes.
  • Enforce a strict Content Security Policy (CSP): Implement a CSP header on the frontend to restrict inline script execution and limit outbound network connections from the browser.

Validate Structure and Transport

  • Enforce HTTPS: Only fetch feeds over HTTPS to protect against Man-in-the-Middle (MitM) tampering, and strictly validate SSL/TLS certificates.
  • Verify Content-Type: Verify that the server response matches expected MIME types (such as application/rss+xml, application/atom+xml, or application/xml) before feeding the payload to the parser.
  • Validate against a Schema: Use XML Schema Definition (XSD) or a strict RSS/Atom validation routine to ensure the payload conforms to the expected structure before further downstream processing.
